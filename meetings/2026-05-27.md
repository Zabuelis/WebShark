    * It was finally decided to replace scapy with tshark to allow for better expansion, faster processing and remove the constraints created by Scapy.
    * The main noticeable difference is that tshark uses relative sequence and acknowledgment numbers, meaning that for each TCP flow the sequence and acknowledgment numbers will start from 1.
2. Faults in TCP flow reassembly.
    * The logic responsible for handling new flows was faulty. In the event where a SYN packet would be retransmitted the algorithm would create a new flow.
